# Versioned policy delivery recovery

Status: implemented typed foundation; other job kinds, financial consumers and scheduled dispatch remain pending.

The existing activation event is the addressable job. The catalog GET returns actual persisted state, version, immutable policy identity/version/hash, timestamps, single-item completion, current and lifetime attempts, finite redacted errors and immutable recovery receipts. It does not run delivery or expire leases. No lease token, recipient identity, arbitrary payload or provider error text crosses the response boundary. Policy reads expose a delivery link only when the current reviewer can see the event under RLS.

Job read/retry authority requires the finite policy_reviewer grant plus current administrator or finance authority, company access, and the immutable activating principal. Ordinary admin/finance authority alone is insufficient. Another reviewer cannot take ownership. Both service and restricted SQL boundaries enforce scope; organization locks serialize writes with membership changes.

Only failed work can be requeued. Retry requires a strict reason, If-Match and Idempotency-Key. Current source/version/hash and recipient eligibility are checked before durable replay. Identical repeats return the original queued response even after delivery; changed input conflicts. New stale versions receive 412. Delivered/cancelled states cannot be reopened, and pending/live/expired leases use the existing worker claim path, not manual recovery.

An engineering bound permits three manual recovery cycles after the initial three attempts, for twelve lifetime attempts. A recovery cycle resets only its local attempt counter; total_attempts never resets. The trigger advances the job version on every real transition and increments lifetime attempts on every claim. A retry receipt records the prior version, reason, principal, request and time; UPDATE/DELETE are forbidden. Receipt, pending transition, metadata audit and original response commit or roll back together. Direct failed-to-pending writes without a valid scoped receipt are rejected. Recipient/source eligibility is rechecked even if a receipt was inserted separately.

Retry returns 202 with concrete JobResult, Location and ETag. It only queues work; a separately invoked bounded scoped worker performs the effect. No HTTP worker endpoint, global credential, hosted database reset, automatic scheduler or external notification is introduced. Migration 0006 expands existing data and backfills lifetime attempts without changing previous sources or completed states. Older scoped worker queries remain compatible; database triggers own technical version/lifetime counters.

Acceptance boundaries are in contract/jobs, integration/outbox and browser approval-controls: typed status privacy, ordinary/other-scope denial, concurrent original-result replay, stale versions, recipient/reviewer revocation, immutable receipts, twelve-attempt exhaustion, transaction rollback, reason/confirmation cancellation/success, persisted history, explicit refresh and 360px layout. Broader R1 job producers must define their own input schema, current authorization and source uniqueness before reusing recovery machinery.
