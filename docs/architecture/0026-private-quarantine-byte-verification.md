# Private quarantine byte verification

K018 source review needs actual retained content. This prerequisite provides a strict file declaration, content identification and an internal bounded private S3 reader. It does not create document records, upload grants, scan decisions, retention holds, download links or review authority. No public operation or permission is enabled.

Evidence is JPEG, PNG or PDF, with a matching extension, a plain display filename, a positive integer size up to 10 MiB and a lowercase SHA-256. Object keys are derived from validated organization/entity/document UUIDs, never filenames or client paths. MIME is checked against actual signatures and terminal markers, and the actual size and hash must match. This is content identification, not a full image/PDF decoder, sanitizer or malware scanner. A signature-valid document may still be malicious. No result is labelled clean.

The calling application service must first recheck current membership and owner-domain access, then load the reference from a trusted scoped repository. The byte reader performs an additional scope check before contacting storage. The reference pins the provider ETag and, when available, object version. Conditional reads prevent silently accepting a replaced quarantine object; ETags are concurrency tokens, not content hashes. Response headers, returned version, encoding and range are checked. Streams are independently bounded by the declared size, incomplete/extra bytes are rejected, and rejected streams are closed. Reads have a 15-second abort deadline and provider errors are redacted.

The return value includes validated bytes and metadata only. It confers no retention or scan status. Future completion must persist actual source ownership, captured object identity, immutable scan/capture evidence and holds before review can consume it. Missing scanner capability must still block live file release. Demo fixtures must be explicitly labelled through that future workflow, not inferred from a valid file signature.

Unit tests cover content spoofing, unsupported extensions, traversal/header filenames, invalid limits/hashes, exact version/ETag checks, encoded/ranged responses, streamed overrun/truncation, unavailable objects and redacted failures. Real isolated private-storage tests upload an actual PNG, restart the provider, verify its retained bytes, deny anonymous access, reject an incorrect declared hash and foreign scope, and reject an overwritten object. These do not prove database document persistence, malware scanning, authorized browser uploads or complete K018 acceptance.

The conditional-read contract follows the [S3 GetObject API](https://docs.aws.amazon.com/AmazonS3/latest/API/API_GetObject.html) and the [installed JavaScript v3 command](https://docs.aws.amazon.com/AWSJavaScriptSDK/v3/latest/client/s3/command/GetObjectCommand/). Existing private S3-compatible storage and dependencies are preserved; no provider, credential, hosted data, environment or protection setting is changed.
