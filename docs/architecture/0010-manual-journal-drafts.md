# Manual journal drafts

The first K014 slice adds five catalog operations: journal list/create/read/patch/cancel. It does not expose submit, approve, reject, post or reverse, and does not complete K014 or R1.

The maker supplies dates, description and 2–500 balanced NPR lines. Account master versions, source identity, creator, updater and scope are server-owned. Strict request schemas reject computed or approval fields, account-version overrides and unsupported dimensions. Current ordinary accounts and same-entity branches are checked under the organization mutation lock. Saving a draft does not require an active posting policy or fiscal period; those checks belong at submission/posting. An archived account can remain visible in historical draft snapshots, but cannot be used by a fresh save.

`manual_journal_drafts` stores the current head. `manual_journal_revisions` retains each saved or cancelled revision. `manual_journal_results` holds private original create/cancel results under entity, principal, operation and key. Runtime has scoped read access to heads/revisions and no direct writes or result access. Two finite definer functions own validation, head changes, immutable revisions, audit and private receipts. Raw posting/source-producer/numbering privileges remain withheld. No administrator connection is imported into the web application.

Create/cancel replay rechecks current authority before returning the original result, including after later edits or cancellation. Changed key content conflicts. PATCH merges only editable fields after the organization lock and enforces the expected head version. Competing edit/cancel commands cannot overwrite a newer head. Runtime mutation denial and append-only revision/receipt triggers preserve evidence. The migration administrator remains an explicit operational trust boundary for the mutable draft head, not a web authority.

Database migrations are forward-only after application: 0012 establishes the draft boundary, 0013 uses the existing metadata-only audit schema, and 0014 explicitly groups JSONB dimension extraction. Earlier applied files were preserved; neither repair touches hosted data. Exact response totals are recomputed from stored decimal-string lines through the domain validator, avoiding JSON numeric precision loss for large amounts.

The responsive workspace provides line addition/removal, visible read-only/cancelled states, reasoned cancellation confirmation and explicit stale-version reload. Account choices are bounded to the first hundred chart rows and that limitation is shown. The API can preserve scoped branches; no unimplemented branch or financial command button is displayed. Broader account search, submission dependency invalidation, independent review, source consumption, reversal dependency guards and financial event delivery remain subsequent work within R1.

Acceptance evidence belongs in the engineering registers: strict contracts, actual restricted-role PostgreSQL replay/race/isolation/atomicity tests, and a browser story from sign-in through create/edit/reload/cancel to retained database revisions. No fictional demo draft is represented as a posted or live-company amount.
