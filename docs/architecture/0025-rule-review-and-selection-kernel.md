# Rule evidence and selection kernel

This K018 prerequisite adds internal evidence-validation, evaluator-test and applicability-selection primitives. It does not expose verify/activate/retire operations, persist review decisions, certify law, release a file or authorize posting. The document workflow and immutable lifecycle records are still required. K019 remains gated.

Review preparation requires a scoped draft, a different actor with designated rules.verify authority, the exact selected retained source documents and declared sections. The kernel hashes actual supplied retained bytes, rejects empty/oversized content, matches every source URL/title/hash/section, checks ownership and retention holds, and excludes quarantined/rejected evidence. A labelled demo fixture can support only a synthetic rule in a demo company. A live rule needs clean, non-demo evidence. Scan status and storage provenance must come from trusted document repositories; an HTTP client cannot certify them. The returned receipt excludes bytes and is deeply frozen for its finite metadata.

UTC instants are normalized to six fractional digits before comparison. Inputs beyond microsecond precision are rejected rather than truncated. A future capture or a verification preceding rule creation is invalid. AD applicability intervals remain half-open.

Evaluator tests use an independent BigInt rational oracle, not the Decimal evaluator to generate its own expected results. Seven bounded cases cover zero, paise rounding, the synthetic service fixture, huge exact values and the supported money limit. Expected overflow must actually occur. The receipt binds rule ID, source version, stored fingerprint, the complete canonical policy hash, evaluator version and test-suite version. It has no invented persisted ruleTestRunId. A mutation test proves wrong evaluator output fails this suite.

Selection requires one active, exact-scope/kind/event/code/date candidate with independent, current content/version-bound review and successful complete test receipts. Missing, expired, inactive, unsupported, wrongly scoped or synthetic-for-live rules never fall back to zero tax. Overlapping active candidates block selection even if one has defective evidence. Selection rechecks retained metadata and returns a frozen calculation definition and source references. It does not activate or post anything.

The scoped application diagnostic reads at most two applicable draft rows and obtains the demo profile from the database, not request input. Current storage holds only drafts and has no persisted review/test receipts, so all actual draft selections fail closed with RULE_NOT_VERIFIED. Its read transaction is not a financial posting permit. Future posting must lock and load actual lifecycle, retained-document/scanner, account-mapping and period dependencies in the same atomic posting transaction.

No new public API, permission grant, schema migration or UI control is added by this prerequisite. Evidence bytes in unit tests are synthetic in-memory content; they do not prove an S3 upload, malware scan, persisted review or complete K018 acceptance. Those remain explicit next implementation gates.
